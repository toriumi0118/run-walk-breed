## Phase 1: コアゲームループ

Godot 内で完結するゲームの中核部分。ネイティブ連携なしで動作確認できる状態を目指す。
**全てのビジュアルはプレースホルダー（矩形・円・ラベル）で実装し、後からアセット差し替えのみで対応する。**

### プレースホルダー方針

コア実装ではアセットを一切作成しない。以下のルールでビジュアルを仮表現する：

| 要素 | プレースホルダー表現 | 差し替え対象 |
|------|---------------------|-------------|
| ペット | 色付き円（ColorRect / Sprite2D）+ タイプ名ラベル | スプライトシート / アニメーション |
| スキル発動 | フラッシュ（画面の色変化）+ テキスト表示 | エフェクトアニメーション |
| HP バー | TextureProgressBar or ColorRect | デザイン済み UI アセット |
| ボタン / UI | Godot デフォルトテーマ + ラベル | カスタムテーマ（ui_theme.tres） |
| アイコン類 | 色付き矩形 + 頭文字ラベル | アイコン画像 |
| 背景 | 単色 ColorRect | 背景イラスト |
| BGM / SE | 無音（AudioManager は接続済み） | サウンドファイル |

**差し替えを容易にする設計原則：**
- ビジュアルは全て `@export` 変数で外部から注入可能にする
- シーンのルートにプレースホルダーノードを配置し、実アセットのシーンに丸ごと差し替え可能にする
- スプライトは `Sprite2D` ノードに統一し、テクスチャ差し替えだけで済む構造にする
- サウンドは `AudioManager` 経由で再生し、ストリームの差し替えだけで済む構造にする

## 備考

- Phase 1 はネイティブ機能なしで動作確認可能（ダミーデータで育成・バトルをテスト）
- Phase 1 は全てプレースホルダーで実装。ロジックが正しく動くことを最優先
- Asset Track は Phase 1〜4 と並行して独立に進行可能
- アセット差し替えは `@export` 変数とシーン構造により、コード変更なしで可能
- Phase 2 と Phase 1 の後半は並行作業可能
- Phase 3 のバックエンド選定は早めに検討開始すると Phase 2 との統合がスムーズ
